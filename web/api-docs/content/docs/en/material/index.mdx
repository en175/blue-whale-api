title: Material Library Overview

The material library API provides create/read/update/delete for **virtual (AIGC) asset groups and assets** plus **real-person (LivenessFace) verification**, through two equivalent entry points: the gateway path form and the Volcengine Ark-compatible query form. Once created, materials can be referenced in [video generation](../video/submit) via `asset://<asset-id>`.

## Endpoints

| Form | Endpoint | Business errors | Session actions |
| --- | --- | --- | --- |
| Gateway (path) | `POST /api/material/{Action}` | `{"ResponseMetadata":{},"ResponseError":{...}}` | Returned unwrapped |
| Ark-compatible (query) | `POST /?Action={Action}&Version=2024-01-01`<br />alias: `POST /api/ark?Action={Action}&Version=2024-01-01` | `{"ResponseMetadata":{"Error":{...},"RequestId":"..."}}` | Wrapped in `ResponseMetadata` + `Result` |

Request bodies and ownership checks are **identical** between the two forms — only the URL shape and the response envelope on errors differ. `Version` is optional in the query form: when omitted the gateway forwards `2024-01-01`.

`Action` values fall into three groups — see [Asset Groups](../material/groups), [Assets](../material/assets), and [Real-Person Verification](../material/real-person).

## Authentication

Same as the rest of the platform — Bearer authentication with an API key:

```bash
Authorization: Bearer sk-YOUR-KEY
```

> Authentication failures (missing/invalid/disabled key) return `401` with an OpenAI-compatible error (`type: new_api_error`), **not** this module's `ResponseError` envelope — see [Authentication](../authentication).

## Response Formats

Two formats (unified to the gateway's actual response shape):

**CRUD envelope** (path form, and success responses of the query form):

```json
{
  "ResponseMetadata": { "RequestId": "req_xxx", "Action": "ListAssets", "Version": "2024-01-01", "Service": "ark", "Region": "cn-beijing" },
  "Result": { }
}
```

**Session direct format** (path form only — `CreateVisualValidateSession` / `GetVisualValidateResult`):

```json
{ "BytedToken": "bt-xxx", "H5Link": "https://.../verify", "CallbackURL": "https://example.com/cb" }
```

> On the Ark-compatible query form, session responses are wrapped instead: the same fields appear under `Result`, next to a `ResponseMetadata` object.

## Error Codes

Business-layer errors (returned by the gateway or normalized from upstream) use:

```json
{
  "ResponseMetadata": {},
  "ResponseError": { "Code": "InvalidParameter", "Message": "invalid parameter" }
}
```

> The Ark-compatible query form returns the same `Code` / `Message` under `ResponseMetadata.Error` instead (with `RequestId` alongside).

| HTTP | Code | Description |
| --- | --- | --- |
| 400 | `InvalidParameter` | Invalid request parameter (e.g. empty `GroupIds` or missing `Filter.GroupType` in `ListAssets`, name containing `<`/`>` or too long) |
| 404 | `NotFound` | Resource not found or **not owned by the current API key** (ownership check, returned by the gateway) |
| 404 | `InvalidActionOrVersion` | Unknown `Action` (returned upstream) |
| 500 | `InternalError` | Upstream internal error |
| 502 | — | The gateway failed to query upstream (e.g. a just-created real-person verification session not yet queryable); retry shortly |
| 401 | — | Authentication failures use the OpenAI-style error (see "Authentication"), not listed here |

## Ownership Isolation

Materials are isolated by the **account owning the API key**:

- Group operations (`GetAssetGroup` / `UpdateAssetGroup` / `DeleteAssetGroup`), `ListAssetGroups`, `ListAssets`, `CreateAsset`, `GetAsset`, `UpdateAsset`, and `DeleteAsset` all verify that the target belongs to the current API key; unauthorized access returns `404 NotFound` (not distinguishing missing vs. unauthorized, to avoid probing).
- `GetAsset` / `UpdateAsset` / `DeleteAsset` resolve ownership by calling upstream `GetAsset` and checking the returned `GroupId`; if upstream fails or returns no `GroupId`, the request is rejected.
- `GetVisualValidateResult` only returns a `GroupId` for sessions created by the same API key; unknown or other-key tokens return an empty `GroupId` without querying upstream.
- The Ark-compatible entry uses the same isolation rules as the path entry.

## Referencing Materials

Once created, materials / real-person groups can be referenced in [video generation](../video/submit) via `asset://<asset-id>`:

- Virtual asset: `asset://Asset-xxx`
- Real-person material: the returned group id `group-xxx`, referenced as `asset://group-xxx`

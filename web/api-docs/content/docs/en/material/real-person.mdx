---
title: Real-Person Verification
description: H5 liveness verification loop for real-person (LivenessFace) materials (CreateVisualValidateSession / GetVisualValidateResult)
---

Real-person materials (LivenessFace) require an H5 liveness verification loop: first create a verification session to obtain `H5Link` and `BytedToken`, have the verifier open the link and complete liveness verification, then query the result with `BytedToken`. **Session endpoints return the direct format** (no `ResponseMetadata`/`Result` envelope).

> **Ark-compatible entry:** the same Actions also work as `POST /?Action={Action}&Version=2024-01-01` (alias `/api/ark`). There, session responses are **wrapped** into `ResponseMetadata` + `Result` instead of the direct format — see the [endpoint comparison](../material/index#endpoints).

## CreateVisualValidateSession — Create a Verification Session

### Request

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `Name` | string | No | Group name, used as the ownership group name after verification |
| `CallbackURL` | string | Yes | Client callback URL (the gateway 302-redirects to it after verification); missing → `400 MissingParameter.CallbackURL` |
| `ProjectName` | string | No | Project name |

```bash
BASE_URL="https://yunjizi.cn"   # Domestic; overseas use https://api.yunjizi.cn

curl "$BASE_URL/api/material/CreateVisualValidateSession" \
  -H "Authorization: Bearer sk-YOUR-KEY" \
  -H "Content-Type: application/json" \
  -d '{"Name":"My real-person group","CallbackURL":"https://example.com/cb","ProjectName":"default"}'
```

### Response

Direct format (no envelope):

```json
{ "BytedToken": "bt-xxx", "H5Link": "https://h5.example.com/verify", "CallbackURL": "https://example.com/cb" }
```

`BytedToken` is the session identifier (used to query the verification result), and `H5Link` is opened by the verifier to complete liveness verification. Once verification completes, the gateway 302-redirects to the `CallbackURL` with the verification result, and the `CallbackURL` in the response is the value you passed in.

## GetVisualValidateResult — Query the Verification Result

### Request

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `BytedToken` | string | Yes | The `BytedToken` returned when creating the session |

```bash
BASE_URL="https://yunjizi.cn"   # Domestic; overseas use https://api.yunjizi.cn

curl "$BASE_URL/api/material/GetVisualValidateResult" \
  -H "Authorization: Bearer sk-YOUR-KEY" \
  -H "Content-Type: application/json" \
  -d '{"BytedToken":"bt-xxx"}'
```

### Response

Direct format (no envelope):

```json
{ "GroupId": "group-xxx" }
```

> Note: after verification completes, the real-person group id `group-xxx` is returned:
> - Token not found / not owned by you → `200` + `{"GroupId":""}` (local fail-closed, no upstream call, no leakage)
> - Session exists but verification incomplete → the gateway queries upstream once: `200` + `{"GroupId":""}` when queryable (keep polling); `502` right after creation if not yet queryable (retry shortly)
> - Verification complete → `200` + `{"GroupId":"group-xxx"}`

The real-person group id `group-xxx` returned after verification can be referenced in [video generation](../video/submit) via `asset://group-xxx` (see [Material Library Overview](../material/index)).
